# ADR-0001. Способ развёртывания (деплоя) кода на сервере
- Статус: принято
- Дата: 2026-10-03

## Контекст
Для проекта TimeCapsule необходимо выбрать способ доставки обновленного кода с локального компьютера разработчика на сервер EC2. Код должен загружаться быстро, с сохранением структуры проекта и версионированием, чтобы обеспечивать стабильную работу приложения после выпуска новых версий.

## Решение
Используем ручной `git pull` на сервере EC2. Код сначала пушится с компьютера разработчика в репозиторий GitHub (`git push`), а затем скачивается на сервере из этого репозитория.

## Рассмотренные альтернативы
- **Копирование через `scp`**.  
  Плюсы: не требует настройки Git и авторизации через токены на сервере.  
  Минусы: копирует файлы напрямую, без истории версий. При каждом деплое нужно прописывать длинные команды с путями ко всем измененным файлам, либо копировать всю папку целиком, что неудобно, долго и повышает риск человеческой ошибки.
- **Скрипт `deploy.sh`**.  
  Плюсы: автоматизирует процесс, позволяет добавить шаги вроде установки зависимостей или миграций баз данных одной кнопкой.  
  Минусы: требует дополнительного времени на написание, отладку и поддержку bash-скрипта. Для текущего этапа развития проекта это избыточное усложнение.

## Последствия
- Плюс: на сервере всегда сохраняется связь с системой контроля версий (GitHub). Можно легко проверить статус (`git status`), посмотреть историю коммитов или откатиться к предыдущей версии с помощью стандартных команд Git.
- Минус: процесс не полностью автоматизирован. При каждом деплое требуется подключаться к серверу по SSH, переходить в нужную папку и вручную выполнять `git pull`, что требует ввода учетных данных (например, PAT-токена), если они не сохранены в системе сервера.
